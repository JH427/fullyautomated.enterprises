## Problems to fix next

Important context: the current labs/products content is demo UI data, not real public FAE work.

That changes the immediate task:
- do not spend too much time polishing fake specifics
- treat the current entries as temporary scaffolding
- replace them with real experiments, notes, and incubation records as they are created

Immediate implication:
- the first real content work should be creating a believable methodology page and a small backlog of actual experiments/products worth running, not perfecting synthetic case-study prose

### 2. Product framing

Products should read as incubation records, not launch pages with fake activation energy.

Recommended posture:
- what problem this emerged from
- what exists today
- what is still unknown
- whether there is a public artifact or repo
- avoid disabled CTA theater unless a real signup path exists

### 3. Evidence density

Every lab or product page should ideally point to at least one of:
- a real repository
- a public note
- a design/spec artifact
- a methodology page
- a public output

### 4. Replace demo entries with real seeds

Before expanding the site, decide which current placeholder items should be:
- removed entirely
- rewritten into real experiment proposals
- replaced by new work generated by Rick and Greg
